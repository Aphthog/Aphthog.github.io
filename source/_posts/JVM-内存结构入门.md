去年有次线上服务 OOM，我把 dump 拉到 MAT 里看，堆上有个 Map 占了几个 G。当时我对 JVM 内存的理解基本只有"堆"——对象放堆里，不够就 OOM。后来跟同事聊才知道，JVM 把运行时内存分了五个区域，堆只是其中之一，还有方法区、虚拟机栈这些，而且有些是线程私有的。这篇把这些区域过一遍。

## 运行时数据区五块

下面是我画的示意图，方便对照着看：

```
            JVM 运行时数据区
  ┌─────────────────────────────────┐
  │         线程私有                  │
  │  ┌─────────┐ ┌───────────────┐  │
  │  │ 程序计数器 │ │  虚拟机栈      │  │  ┌────────────┐
  │  └─────────┘ │ （栈帧列表）    │  │  │  堆          │
  │              └───────────────┘  │  │ （共享）      │
  │  ┌───────────────┐              │  │  + Eden      │
  │  │ 本地方法栈      │              │  │  + S0 / S1   │
  │  └───────────────┘              │  │  + 老年代     │
  │                                │  └────────────┘
  └─────────────────────────────────┘  ┌────────────┐
                                       │ 方法区      │
                                       │ （共享）    │
                                       │  元空间     │
                                       └────────────┘
```

五块区域按是否线程共享分两类：程序计数器、虚拟机栈、本地方法栈是**线程私有**的——每个线程都有自己的副本；堆和方法区是**线程共享**的。

### 程序计数器

线程私有的一小块空间，存的是当前线程正在执行的字节码指令地址。如果正在执行 Java 方法，PC 指向下一条要执行的指令；如果是 native 方法，PC 是 undefined——native 方法不经过字节码。它是 JVM 规范里唯一没有 OutOfMemoryError 的区域。

### 虚拟机栈

每个线程启动时 JVM 会分配一个栈，里面装的是栈帧（Stack Frame）。每调用一个方法就压入一个帧，方法返回就弹出。每个栈帧里装着局部变量表（方法的参数和局部变量）、操作数栈（字节码指令的操作数）、动态链接（指向运行时常量池中的符号引用）和方法出口等。

栈大小可以用 -Xss 参数设置。递归没写终止条件会导致 StackOverflowError；动态扩展时内存不够会抛 OOM。

### 本地方法栈

功能上跟虚拟机栈类似，专为 native 方法服务。HotSpot 实际把两个栈合二为一了，但概念上它们仍然是独立的。

### 堆

堆是所有对象实例分配的地方，也是 GC 的主战场。它是线程共享的，但 JVM 给每个线程分配了一块私有的缓冲区（TLAB，Thread Local Allocation Buffer）来降低对象分配时的锁竞争。

堆被分代管理：

| 区域 | 说明 |
|---|---|
| Eden | 新对象默认分配在这里，大部分很快变成垃圾 |
| Survivor 0 / Survivor 1 | 经过一次 Minor GC 还活着的对象移到 Survivor，之后在 S0 和 S1 之间来回复制 |
| 老年代 | 熬过多轮 GC（默认阈值 15 次）的对象晋升到这里 |

Eden 加两个 Survivor 合称年轻代。以分代收集器为例（如 Parallel Scavenge），默认 Eden : Survivor = 8 : 1 : 1，可以通过 -XX:SurvivorRatio 调整。大对象如果超过 -XX:PretenureSizeThreshold 的阈值就直接进老年代，不走年轻代。

### 方法区

方法区存的是类信息（类名、方法数据、字段信息）、运行时常量池、静态变量、JIT 编译后的代码等。

在 JDK 7 及之前，方法区的实现是**永久代（PermGen）**，属于堆的一部分，默认空间不大，加载大量类时容易 OutOfMemoryError: PermGen space。从 JDK 8 开始永久代被移除，取而代之的是**元空间（Metaspace）**，使用本地内存（native memory），默认只受操作系统可用内存的限制。不过如果代码里用 CGLIB 之类框架无限生成类，元空间一样会 OOM。

## 一张速查

| 区域 | 线程私有？ | 异常类型 |
|---|---|---|
| 程序计数器 | 是 | 没有 OOM |
| 虚拟机栈 | 是 | StackOverflowError / OOM |
| 本地方法栈 | 是 | StackOverflowError / OOM |
| 堆 | 否（共享） | OOM（最常见） |
| 方法区（JDK 8+ 元空间） | 否（共享） | OOM |
